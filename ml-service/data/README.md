# Data Directory — Synthetic Placeholder Data

> ⚠️ **All files in this directory are SYNTHETIC / PLACEHOLDER data.**
> They are generated by `../generate_data.py` using seeded random generation
> with realistic variance. Replace them with real database exports before
> going to production.

---

## File Schemas

### `destinations.json`
Array of destination objects:
```json
{
  "id": "dest-001",
  "name": "Tarkarli",
  "state": "Maharashtra",
  "lat": 16.005,
  "lng": 73.469,
  "vibe": ["beach", "nature", "adventure"],
  "thematicTags": ["beaches", "wildlife", "food"],
  "bestMonths": ["November", "December", "January", "February"],
  "rating": 4.6,
  "startingPrice": 2500,
  "popularityTier": "gem",
  "tierCategory": "Tier-3",
  "affordabilityIndex": 78,
  "sustainabilityScore": 82,
  "currentCapacityLoadPct": 35,
  "isOvertouristed": false
}
```
**50 destinations** covering major Indian states.

---

### `attractions.json`
Array of attraction objects (8 per destination, top 15 destinations = 120 records):
```json
{
  "id": "attr-0001",
  "destinationId": "dest-001",
  "name": "Tarkarli Beach",
  "lat": 16.008,
  "lng": 73.475,
  "category": "beach",
  "avgVisitDurationMins": 90,
  "openHour": "06:00",
  "closeHour": "18:00",
  "indoorOutdoor": "outdoor",
  "estimatedCost": 0
}
```
Valid categories: `beach | fort | restaurant | museum | market | temple | nightlife | park | waterfall`

---

### `reviews.json`
Array of review objects (10 per destination = 500 records):

```json
  "rating": 4,
  "text": "Beautiful location but rooms were a bit dirty. Staff was helpful though.",
  "date": "2024-03-15"

```

Array of monthly climate records (12 months × 50 destinations = 600 records):
```json

  "month": "July",
  "avgTempC": 27.4,
  "avgRainfallMm": 620,
  "avgHumidityPct": 87,

```

---

## How to Replace with Real Data

1. Export your real destination/attraction/review/climate data in the schemas above.
2. Drop the new files into this directory (same filenames).
3. Restart the service — it will automatically rebuild the recommendation matrix,
   retrain the price model, and retrain the weather-fit model on the new data.

> The model files under `../models/` are invalidated automatically when you
> restart after replacing data (the service trains fresh on startup if needed).
